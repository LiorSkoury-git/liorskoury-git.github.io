Multi actor control and manufacturing

Manufacturing can require multiple machines and people to share work across many steps. This research branch explores how a common task model can assign work according to each actor’s capabilities, connect them through general interfaces, and coordinate their actions in space and time.

01 / Work shared by capability

Manufacturing brings together many kinds of work: moving material, positioning parts, applying treatments, making connections, and checking results. Each process and each action within it calls for particular capabilities. Thinking of machines, people, and software as actors allows a process to be organised around what each can contribute. Tasks can be assigned to an individual actor or shared among several, according to their skills, tools, reach, and availability. The composition of the team and the conceptualisation of tasks become part of planning the manufacturing process.

02 / One interface, many actors

The shared task model alongside the virtual actor interface provides the basis for this exchange. Each task connects an intended action to its design element, geometry, required tools, instructions, and execution record. Actor-specific interfaces translate that description into robot commands, machine operations, or guidance for a person. Status and results return through the same connection. The virtual actor interface connects each actor to the system and guides tasks through a repeating cycle of preparation, dispatch, completion monitoring, and result processing. The engine software can then work with a common task structure while each actor uses the controls and instructions appropriate to its role.

03 / Parallel work under constraints

With tasks connected through a common interface, coordination can address their relationships in space and time. Actors may share a workspace or tool, depend on a previous operation, or need to finish before a material deadline. Scheduling combines these conditions with actor capabilities to identify work that can only happen in sequence, work that can be done in parallel, and tasks that can be allocated according to the availability of the actor. This flexible task sequencing, which can adapt along the process, is achieved by representing tasks and their dependencies as an adaptable graph structure.

04 / People within the system

For workers, a coordinated process must be understandable as it unfolds. People need to know what work is available, where it belongs, and when other actors are ready. Their roles can include assembly, machine operation, inspection, and supervision. Interfaces must support both carrying out an assigned task and exercising judgement about the process. Confirmations and interventions bring those decisions back into the shared task record, allowing human participation to inform the progression of work through dedicated devices such as AR gear, tablets, or smart watches.

05 / Studies

These concepts were explored through studies of human–robot collaboration, collective robotic construction, and multi-robot timber manufacturing. The studies examined how shared tasks connect different actors, how interfaces support worker guidance and supervision, and how scheduling coordinates parallel work under spatial constraints and material deadlines. Simulations, user studies, and physical demonstrators provided complementary evidence of how these approaches operate across different team compositions and fabrication settings.

01 / 06

06 / What this establishes

Across simulations, user studies, and physical demonstrators, the research establishes a framework for organising manufacturing around the capabilities of machines and people. A shared task record links design intent to instructions tailored to each actor, then captures confirmations, status, and results as work proceeds. An adaptable graph of task dependencies supports sequential and parallel work, while interfaces allow workers to carry out, supervise, and intervene in tasks. Workspace conflicts, tool availability, and material deadlines shape which actions can happen together and when a plan needs to change. Representing those relationships explicitly helps the team adjust the process while keeping each actor’s contribution traceable.
